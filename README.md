# 我的路书 · geo-roadbook

把谷歌地球的收藏（KMZ）和奥维互动地图的轨迹（KML）揉成一个**单文件网页**，
按原来的文件夹层级分门别类，勾选才显示，能单独导出某个分类的 KML 给奥维用。

## 成品

`我的路书.html` —— 双击就能开，不需要服务器，不需要装任何东西。
数据全部内嵌在里面，复制到任何设备都能用（底图需要联网）。

当前内置：

- 谷歌地球 `谷歌地球20261019.kmz` —— 21215 个地标（39 个文件夹）
- 奥维 `20261116奥维.kml` —— 955 条记录（861 个标注点 + 94 条轨迹，含 279 万个轨迹点）
- 合计 22170 个地标、40 个顶层文件夹

## 能干什么

| 功能 | 说明 |
|---|---|
| 分类浏览 | 完整保留原文件的文件夹层级，最深 7 层 |
| 勾选显示 | 文件夹前面的方框，勾哪个显示哪个，可以多个叠加 |
| 单条勾选 | 展开文件夹后每条记录也能单独勾 |
| 导出 KML | 任意文件夹右侧「导出」，按原层级生成 KML |
| 导入 | 工具栏「导入」，支持 KML / KMZ，存浏览器本地 |
| 改名 | 双击任意文件夹名或记录名 |
| 删除 | 右侧「删」，删文件夹会连里面的一起删 |
| 底图 | 11 种可选，见下 |

## 制作流程

```bash
# 1. 从 KMZ 提取（谷歌地球）
python extract_ge.py          # -> ge_data.json

# 2. 从 KML 提取（奥维，含 gx:Track 和 MultiGeometry 分段）
python extract_ovital.py      # -> ge_ovital.json

# 3. 合成网页
python make_roadbook.py       # -> 我的路书.html
```

`make_roadbook.py` 会把两份 JSON 合并、建树、gzip 压缩后 base64 内嵌，
前端用浏览器原生的 `DecompressionStream('gzip')` 解压，所以 108MB 的原始 JSON
能压到 43MB 的 HTML，载入 1 秒。

## 踩过的坑

- **iterparse 会清空元素**：`<name>` 一结束就 clear，等父元素 Placemark 结束时再读就是空的，
  所有地标会变成「无名」。必须在元素自己的 end 事件里当场取值。
- **奥维的标注点是 Point**：只有一个坐标，按 LineString 渲染画不出来，会全部消失。
- **MultiGeometry 不能拼**：滇藏铁路在奥维里是 378 个独立 `LineString`，
  全拼成一条会出现大量跨线直线。
- **`gx:Track` 的坐标格式不同**：`<gx:coord>` 是「经度 纬度 高程」空格分隔，
  `<coordinates>` 是「经度,纬度,高程」逗号分隔，两套都要认。
- **双击改名失效**：单击就重建列表会导致双击凑不齐，得给单击加延时。

## 说明

改名、删除、导入的数据都存在**浏览器本地**（localStorage / IndexedDB），
跟这台机器这个浏览器绑定。换设备打开是原始状态。
原始的 KMZ/KML 文件全程没有被修改。
